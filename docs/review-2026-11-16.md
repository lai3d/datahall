# Review, 2026-11-16

A look at the whole project eight weeks after the last merge (2026-09-22, #61). The engineering is in good shape; the
weak spot is the first thirty seconds of a visit, which do not show what the roadmap says the app is for: a stranger
understanding within five minutes why an AI data hall cannot power on.

Estimates are in Claude session hours. Work a person has to do by hand is marked as such.

## What was checked

- `npm run typecheck`, `npm test` (486 tests in 29 files) and `npm run build` on `main` at `824883b`: all pass.
- The production build, opened as a first visit (clean origin) at 1440 × 900 and 390 × 844, plus the powered-on state
  and the first scenario.
- `npm run catalog-check` against today's date, and one HTTP request to each of the catalog's 52 source URLs.
- `npm audit` and `npm outdated`.

Not checked: the analytics. The Vercel account reachable from this session does not hold the `datahall` project and the
`vercel` CLI is not installed, so visits, tutorial completions and share-link opens are unknown. The e2e suite and the
Unity project were not run.

## 1. The first screen does not tell the story

| # | Finding | Evidence | Suggested change |
| --- | --- | --- | --- |
| 1.1 | A first visit lands on a hall that already passes | The default layout is `PRESETS.gb200`; the panel reads "All checks pass" | Land first visits on eight GB200 racks and nothing else, the start of scenario 1 |
| 1.2 | The reasons a hall cannot power on are below the fold | At 1440 × 900 the panel is 3072 px tall; the issue list starts near 1072 px and the power button near 1112 px. A failing hall shows red caps in 3D and no words | Put the verdict, the reasons and the power button in an overlay on the 3D view |
| 1.3 | Powering on barely changes the picture | In the light theme the before and after screenshots differ only by small dots on the links. The social image uses the dark theme, powered on | Dim the scene and let the racks glow on power-on; add a manual theme switch (today it follows the system only) |
| 1.4 | Devices in 3D have no labels | Nothing tells a CDU from an RPP without clicking each one | Show the device name on hover, or a short type label on the device |
| 1.5 | The camera does not frame the hall | The default hall fills about a quarter of the stage, above center, over a wide empty floor | Frame the placed devices after a layout loads |
| 1.6 | The tutorial offer stays up inside a scenario | Starting scenario 1 on a first visit stacks the "New here?" card on the scenario card | Hide the offer while a scenario or the tutorial is running |

About 3 to 4 hours for the group.

## 4. Engineering

- `npm audit` reports five advisories (two high), all in the Vite dev server chain, none in what is deployed; Vite 8.3.8
  clears them. The repository has no Dependabot configuration.
- The entry chunk is 143 kB gzipped and carries both locales, the catalog with all its sources, the report, USD import
  and export and the methodology dialog. Loading the second locale and the rarely used features on demand should save
  30 to 40 kB. First paint was 536 ms locally, so this is not urgent.
- The comment in `web/vite.config.ts` still describes one bundle of about 850 kB that is "not worth splitting"; the
  build has been split since #56.
- 29 `claude/*` branches remain on the remote. They were squash-merged, so git lists them as unmerged; deleting them
  needs the owner's go-ahead.
- The roadmap's Now and Next lists have been empty since 2026-09-20 and the plan ends in mid-December.

About 1 hour for the group, without the branch cleanup.

## Suggested order
